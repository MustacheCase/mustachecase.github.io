Does your CI actually block?

zanadir is an open-source CI/CD security tool. It reads a repository's pipeline, from GitHub Actions to GitLab CI, and reports which security and quality checks are missing, and which are wired so they can never fail the build.

Scan a repository in your browser 
zanadir scan --dir .
zanadir scan --repo github.com/owner/name
zanadir fix --dir .

Present is not protected

A scanner with continue-on-error, --exit-code 0, || true or a push-only trigger is in the pipeline but cannot stop a merge. zanadir grades every control it finds:

enforcingcan fail a merge
partialruns, but not on every change
advisorycannot fail a build
unknownbehind a condition the file cannot settle

What it checks

  • Thirteen categories: SCA, secrets detection, SAST, linting, unit tests, coverage, licences, end-of-life, IaC, supply chain, workflow security, performance testing and agent skill security.
  • Six CI platforms: GitHub Actions, GitLab CI, CircleCI, Bitbucket Pipelines, Azure Pipelines and Jenkins.
  • Into what the jobs call: Makefiles, Taskfiles, tox, goreleaser, reusable workflows, composite actions and CI templates.
  • With --required-checks, whether branch protection requires the check at all.

Mapped to the OWASP Top 10 CI/CD Security Risks, it covers six of the ten from the repository alone. See the mapping.

State of CI security 2026

We scanned 1,000 of the most-starred GitHub repositories with CI. 511 declare no dependency, secret or code scanning anywhere in the repository, and 1 in 6 of those that do run a scanner in CI have one that cannot fail the build. Read the report.
